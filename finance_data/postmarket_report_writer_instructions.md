5. `finance_data/reports/<데이터 기준일>_postmarket.md` 절대경로에 저장한다 (예: `finance_data/reports/2026-09-07_postmarket.md`). 상대경로 `reports/...`로 저장하지 않는다 — 실행 시 유효 작업 디렉터리가 기대와 달라 저장소 루트의 `reports/`(존재하지 않는 잘못된 위치)에 저장된 사고가 있었다(2026-09-30). `reports/` 폴더는 이미 존재한다. 리포트 파일 외의 소스, 템플릿, 데이터 파일은 수정하지 않는다.

2. 핵심 전략 (실제 주문에 설정된 자동 편입 매도 트레일링 스탑):
   - 시장별 수치는 `portfolio_config.md`의 "자동 편입 매도 주문"만 사용한다. 이 지침에 별도 수치를 중복 관리하지 않는다.

3. 절대 금지 사항:
   - 수급 확인 없는 맹목적 매수 금지
   - 구름대 내부(매물대) 진입 금지

   - 눌림목 없이 이미 급등(당일 고점 마감 등)한 자리 추격매수 금지
4. 종목당 최대 비중: 평상시 20%, 사이드카/서킷브레이커가 최근 반복되는 고변동성 구간에는 12~15%로 축소
5. 확인되지 않은 수치는 절대 추측하지 않고 "확인되지 않음"으로 명시. 사실/해석/추정을 구분한다.

## [리포트 작성 시 반드시 적용할 팩트체크 로직]

- "1. 오늘 코스피/코스닥 마감 리뷰"의 실제 등락 결과는 market_data.json의 `index.코스피`/`index.코스닥`(종가/등락률/시가/고가/저가/거래대금, pykrx 종합지수 조회로 확정된 값)을 그대로 쓴다. 더 이상 "지수 필드가 없어 확인되지 않음"이라고 쓰지 말 것. 값이 에러 문자열(예: "확인불가: ...")일 때만 확인되지 않음으로 표시.
- stocks/watchlist_candidates의 각 종목에는 investor 필드(외국인_순매수/기관_순매수/개인_순매수, 해당 종목 개별 수급)가 있다 — 더 이상 "개별 수급 미확인"이라고 쓰지 말고 이 값을 그대로 사용해 방향(순매수/순매도)을 명시할 것. investor 필드가 에러 문자열이면 그때만 "확인되지 않음"
- stocks의 각 종목: cloud_pos가 "구름대 안"이면 → 매물대, 신규 진입 절대 금지 명시
- cloud_pos가 "구름대 아래"면 → 하락 추세, 물림 종목은 대응 대기, 신규 종목은 진입 부적합
- cloud_pos가 "구름대 위"인데 당일 고가권 마감(종가가 고가에 가까움)이면 → 추격매수 경고, 전환선(tenkan)/기준선(kijun) 되돌림 대기 권고
- cloud_pos가 "구름대 위"이고 조정(-1~-3%대 하락)이 나오면서 전환선 위에서 지지 → 추세가 유지되고 있다는 사실로만 서술 (매수 후보로 평가하지 않는다)
- watchlist_candidates 각 항목: flag에 "⚠️ 방향 불일치"가 있으면(외국인 순매수인데 주가 하락) 반드시 경고 표시하고 후보에서 제외. 이 flag는 데이터가 직접 계산한 값만 신뢰하고, 반대 케이스(주가 상승 + 외국인 순매도)까지 임의로 "방향 불일치"로 확장해서 판단하지 않는다.
- 당일 수급 부호만으로 방향 불일치·추세 반전을 단정하지 않는다. tracking_status가 "N일째 관찰 중"으로 여러 날 누적 추적된 종목이 하루 반대 부호의 수급(특히 최근 순위권에 들 정도로 컸던 흐름에 비해 소액인 경우)을 보이면 "방향 불일치"로 격상하지 말고 "단기 차익실현 가능성, 누적 추세 훼손 여부는 확인되지 않음" 정도로 완화해서 서술할 것. 이 경우 "추격매수 금지" 같은 이중 경고도 이 하루치 반대 수급만 근거로 추가하지 않는다.
- flow.프로그램_순매수, flow.코스피/flow.코스닥 각각의 외국인/기관합계/개인 순매수 방향을 종합해서 "오늘 하락/상승이 개별 이슈인지 구조적(프로그램 매도 등) 이슈인지" 해석 추가. 코스피와 코스닥의 수급 방향이 다르면(예: 코스피는 외국인 순매수, 코스닥은 순매도) 반드시 구분해서 언급할 것
- 프로그램매매의 차익_순매수와 비차익_순매수 방향이 다르면(예: 차익 +, 비차익 -) → "차익거래자는 저가매수, 비차익(지수추종)이 매도 주도"로 해석
- "오늘 강한 업종 TOP3"는 scraped_data.json의 sectors 필드(pykrx 업종지수, 해당 거래일 정규장 마감 데이터 — 실제 업종명+등락률+대표종목)를 그대로 사용한다. 종목명으로 업종을 추측하지 않는다. sectors가 비어있거나 조회 실패 시에만 "확인되지 않음"으로 표시. 리포트에 출처를 적을 땐 "네이버 금융 테마"가 아니라 "pykrx 업종지수"로 쓸 것
- "오늘 약한 업종 TOP3"는 scraped_data.json의 weak_sectors 필드(전체 업종 중 등락률 하위 5개)를 사용한다. 단 weak_sectors의 등락률이 실제로는 양수일 수 있다(전 업종이 상승한 날엔 "가장 덜 오른 업종"이 표시됨) — 이 경우 "하락"이라고 쓰지 말고 "상대적으로 상승폭이 가장 작은 업종"처럼 부호에 맞게 정확히 서술할 것
- `swing.pick`, `swing.pick_next`와 그 안의 `점수`는 리포트 끝에 자동으로 붙는 순위 표 전용이다. 본문 어디에도 옮겨 쓰거나 다른 점수(시장점수 등)로 바꿔 쓰지 않는다. 템플릿에 정의되지 않은 점수를 새로 만들어 매기지 않는다.
- 리포트의 주 신호는 추세 돌파(`breakout` 필드)다. 맨 위 🚀 섹션은 파이프라인이 리포트 저장 후 자동으로 붙이므로 직접 쓰지 않는다. 6장·7장은 템플릿 지시대로 `breakout.candidates`·`breakout.sells`만 근거로 쓴다. `breakout`이 null이면 "추세 돌파 데이터 확인되지 않음"으로 표시한다.
- 눌림목 판정(`swing.verdict`의 "매수 유력" 등)과 `technical_rebound_candidates`(역추세 반등 관찰)는 백테스트상 우위가 없어 리포트에서 뺐다. 어디에도 "매수 유력"이라는 표현이나 반등 매수 후보를 쓰지 않는다. `swing` 필드의 이평선·RSI·수급 같은 사실 값은 5장 종목 설명에 근거로 써도 된다(5일 누적 수급은 원 단위라 억원으로 환산).
- scraped_data.json의 top_vol/top_foreign 필드는 현재 크롤링 미작동으로 항상 빈 배열임 — 대신 market_data.json의 candidates(top_value/top_foreign)를 사용할 것

## [절대 준수사항]

- 이 리포트의 독자는 개인 투자자 본인이다. 전문 용어(구름대, 전환선, 기준선, 후행스팬, 눌림목, 프로그램매매 차익/비차익, RSI, MACD, 손익비 등)는 리포트에서 처음 나올 때 괄호로 한 줄 쉬운 풀이를 단다. 점수·등급·지표를 쓸 때는 무엇을 뜻하는지와 어떻게 계산했는지를 반드시 함께 적는다. 설명할 수 없는 숫자는 쓰지 않는다.

- 확인 안 된 숫자(예: pykrx 스캔 실패, 특정 종목 데이터 누락)는 "확인되지 않음"으로 표시, 추측 금지
- 프로그램매매는 market_data.json의 flow.코스피_프로그램매매에 이미 병합되어 있음. program_data.json은 교차 확인용으로 참고
- 리포트 상단에 데이터 기준일(오늘 종가 기준인지 직전 거래일 기준인지)을 명시할 것
- 매수 추천은 하지 말 것 — "원칙에 부합하는지 여부"만 판단하고, 최종 매매 결정은 사용자 몫으로 남길 것
- 오늘 핵심 결론 섹션은 "결론:"으로 시작할 것
- 종목 코드-이름 매칭, 컬럼명 등에서 추측하지 말고 실제 JSON 구조를 그대로 확인해서 쓸 것
- watchlist_candidates가 빈 배열이면 "오늘은 자동 발굴된 관심종목 후보가 없습니다."라고만 표시
- 간밤 글로벌 시장 체크(미국 지수 등)는 이 리포트에 포함하지 않는다 (아침 프리마켓 브리핑 담당)
